# Playwright TDD Framework

Reusable TypeScript test automation framework for UI, API, database, load, and AI-related testing. The project uses Playwright Test, page objects, shared commons, environment-based configuration, and JSON test data.

## Prerequisites

- Node.js and npm
- JavaScript/TypeScript support in VS Code or another editor
- Access to the application and test accounts
- JMeter when running the load-test plan

Install the project dependencies with:

```powershell
npm install
npx playwright install
```

## Project Structure

```text
commons/
	ai/       Shared AI helpers
	api/      Shared API helpers
	db/       Shared database helpers
	jmeter/   Shared JMeter helpers
	ui/       Shared browser and authentication helpers

config/
	config.json          Default URLs and non-secret configuration
	config-timouts.ts    Timeout constants and runtime environment configuration

files/                  Input files and cached authentication data
	auth-cache.json

page-object/
	page-elements/        JSON locators grouped by page
	page-steps/           Page object actions and assertions

testdata/
	ai/data.json          AI test data
	api/data.json         API test data
	db/data.json          Database test data
	ui/data.json          UI test data

tests/
	api/                   API test specifications
	load/                  Load tests and the JMeter test plan
	ui/features/          UI tests grouped by feature

utilities/               Database, Excel, logging, and PDF utilities
playwright.config.ts     Playwright projects, timeouts, reporters, and artifacts
playwright-reports.json  JSON reporter output
playwright-report/       HTML report output
test-results/            Screenshots, videos, traces, and error context
```

## Configuration and Credentials

`config/config-timouts.ts` loads `.env` values with `dotenv` and builds the runtime configuration. `stage` is the default environment. Set `TEST_ENV` or `ENVIRONMENT` to select another environment.

UI credentials use this precedence:

```text
<ENVIRONMENT>_USERNAME -> USERNAME
<ENVIRONMENT>_PASSWORD -> PASSWORD
```

For example, when `TEST_ENV=stage`, the framework checks `STAGE_USERNAME` and `STAGE_PASSWORD` first, then `USERNAME` and `PASSWORD`.

Create a local `.env` file, or set the same values in CI secrets. Do not commit `.env` or real credentials:

```text
TEST_ENV=stage
STAGE_USERNAME=your-stage-username
STAGE_PASSWORD=your-stage-password
```

PowerShell example:

```powershell
$env:TEST_ENV = "stage"
$env:STAGE_USERNAME = "your-stage-username"
$env:STAGE_PASSWORD = "your-stage-password"
npx playwright test
```

Environment-specific application and API settings follow the same pattern:

```text
STAGE_APP_URL
STAGE_API_BASE_URL
QA_APP_URL
QA_API_BASE_URL
PRODUCTION_APP_URL
PRODUCTION_API_BASE_URL
```

Generic fallbacks are `APP_URL`, `API_BASE_URL`, `API_AUTHORIZATION`, and `API_KEY`. Database settings support `DB_HOST`, `DB_PORT`, `DB_USERNAME`, `DB_PASSWORD`, and `DB_NAME`, with environment-specific prefixes taking precedence.

The available environments are `stage`, `qa`, and `production`. Their default URLs are defined in `config/config.json`. The `qa` and `production` values should be supplied through environment variables when the configured URL is empty or needs to be overridden.

### Login credential flow

The valid-login test reads `runtimeCredentials.username` and `runtimeCredentials.password`, verifies that both values exist, and passes them to `LoginPageSteps.enterValidCredentials()`. The page step types them into the username and password fields before clicking the login button. Invalid-login tests use Faker-generated credentials and do not use the real account credentials.

## Running Tests

Run the complete test suite:

```powershell
npm test
```

Run the type check and formatting check:

```powershell
npm run type-check
npm run lint
```

Run a single test file:

```powershell
npx playwright test tests/ui/features/login/login-tests.spec.ts
```

Run the environment-specific UI commands defined in `package.json`:

```powershell
npm run test:stage
npm run test:qa
npm run test:prod
```

Run by tag or select a browser project:

```powershell
npx playwright test --grep @smoke --project=chromium
npx playwright test --project=firefox
```

The configured browser projects are Chromium and Firefox. Tests run headlessly by default. Screenshots are captured on failure, videos are retained on failure, and traces are collected on the first retry.

## Reports and Artifacts

- `playwright-report/`: HTML report generated by Playwright.
- `playwright-reports.json`: JSON reporter output.
- `test-results/`: failure screenshots, videos, traces, and error context.
- `files/auth-cache.json`: cached authentication state used by shared authentication flows when available.

Open the HTML report with:

```powershell
npx playwright show-report
```

## Development Workflow

1. Add or update page locators in `page-object/page-elements/`.
2. Add page actions and assertions in `page-object/page-steps/`.
3. Keep reusable behavior in `commons/` and test data in `testdata/`.
4. Add the test specification under the relevant `tests/` component or UI feature.
5. Run `npm run type-check` and `npm run lint`.
6. Run the relevant Playwright test, then review the generated report and artifacts.

## Security Notes

- Keep `.env`, authentication state, API keys, bearer tokens, and passwords out of source control.
- Prefer CI secret variables for shared pipelines.
- Treat generated reports and traces as potentially sensitive because they may contain URLs, usernames, or page content.
